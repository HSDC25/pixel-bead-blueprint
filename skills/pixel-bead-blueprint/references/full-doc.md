## 触发词

- "教我拼拼豆" / "陪我拼" / "当我的拼豆老师"（完整六步辅导环）
- "把这张照片变成拼豆图纸" / "生成像素画图纸"（工作流 A）
- "拼豆色号表" / "像素画采购清单"
- "识别一下这张成品/色卡用了哪些色号"（工作流 B）
- "只用我手里有的颜色生成图纸" / "我缺哪些色、要补买多少"（工作流 B）

## 输入

- 图片（照片 / 手绘 / 截图 / AI 生成图——AI 图是合法上游灵感输入，本 skill 负责把它变成可执行图纸）
- **格式支持（2026-10-22）**：JPEG baseline（420/422/444/灰度，EXIF Orientation 1~8 自动转正）/ **progressive JPEG（SOF2 自动转码，见「格式兼容」）** / PNG 8-bit（RGBA/RGB/灰度/调色板）。**不支持**：16-bit PNG、隔行 PNG——抛可读错误。
- 拼豆成品照 / 像素画作品图 / 拼豆图纸 / **紧贴或带间隙的**色卡截图（工作流 B；普通照片被门禁拒绝并提示改走工作流 A）
- 想拼纯主体形状（如「猫形挂件」）：请用户提供**透明背景 PNG**；管线完整消费 alpha——透明格 = 不放豆
- **主体太小** → 先 `--crop x,y,w,h` 裁到主体再生成（900×700 狗脸 96 档只剩 ~9×9 格）

## AI 辅导定位（本 skill 与离线生成的本质区别）

```text
AI 文生图      → 一张「像像素画的图」（拼不了）
离线 APP      → 固定算法 + 图纸文件（用户自己琢磨）
本 skill      → 特征分析 + 视觉推理出参数 + 图纸 + 教学计划 + AI 陪拼 + 复盘回收 ↺
```

**六步辅导环**（详细规程见 references/ai-tutor-protocol.md ）：

1. **了解学员**：经验档位 / 单次时长 / 辨色困扰 / 库存——先问再开工，档位不符主动建议降网格并讲理由。
2. **看图 + 特征分析**：视觉理解构图与必保细节（机器测不出）× `--analyze` 特征 JSON（机器测得准），推理决策、**禁查表**。
3. **生成图纸 + 辅导计划**：`--teach` 落盘 `coaching.md`（难度评定 / 工时场次 / 每场校验点 / 该图专属易错点）。
4. **讲解互动**：带学员读图纸、讲管线决策（处理报告回显翻译成人话）、两版 compare.png 对比让学员参与决策。
5. **施工期陪拼**：按 coaching.md 场次推进，每场验收（ASCII 矩阵逐行核 / 分块对块）；反馈走应对思路（先分类根因再动手）。
6. **完工复盘 + 库存回收**：对照 compare.png 复盘 → 成品照 `--scan` 回补库存 → 下次难度递进建议。

**辅导质量红线**：不静态映射参数；不整份念 coaching.md；参数决策必须答得出「为什么」。

## 可选参数（与 CLI 一一对应；默认值以本表为准）

| 参数 | CLI | 范围 | 默认 | 作用 |
|---|---|---|---|---|
| 网格数 | `--grid N` | 8~8192 | 64 | 细节保留率（64 格约 8%，128 约 12%，256 约 17%）；>512 为超大档 |
| 色盘 | `--palette <别名\|json>` | mard(221) / mard291 / perler(118) / artkal-c197 / artkal-m221 / 同 schema 自定义 JSON | MARD 221 | 色号体系；Perler/Artkal 用短码 P1.. / 数字码，色号表带产品号与名称 |
| 映射算法 | `--dither nearest\|fs` | 最近色 / FS 抖动 | **最近色** | 干净色块 vs 渐变纹理；照片默认 nearest（FS 实测增噪） |
| 边缘描边 | `--outline 1` | 开 / 关 | **关** | 轮廓保留（风格项） |
| 杂色清理 | `--clean 0\|1\|2` | 关 / 标准 / 强力 | 标准(1) | 孤点去噪；FS 模式自动跳过；**内建暗线保护**（暗格 L\*<30 且有暗邻居 = 线段结构，不被亮色多数派吞） |
| 格内取样 | `--sample dominant\|avg` | 主色桶 / 均值 | **主色桶** | dominant = 格内「像素数最多的颜色桶」取均值（APP cellDominantGrid 口径）+ **墨线保真**：格内暗像素（比主色暗 ΔY≥60）占比 ≥ `--ink-min` 且墨线穿过格子中央（v1.2.0 中央判据；抗锯齿毛边只贴边、中央覆盖≈0 ⇒ 邻格留浅，线宽不再抖动；对称骑线格仍入线）时整格取线色——简笔画/Logo 必配；avg = 旧均值口径（对照实验用）。细线断线时调低 `--ink-min` 到 0.10 |
| 区域锁定 | `--region-lock DE` | 0（关）/ 6~16 | **关** | 源色 4 邻域连通（相邻格 ΔE≤DE）成区域，面积 ≥`--lock-min`(默认8) 格的整块改写为「区域源色中位」最近色号。治**大色块被光照渐变劈成多个近似色号**（Mondrian 64 档实测：44 色 5.36% 翻转 → 5 色 0.11%）。⚠️ 几何图/平色插画/扫描件建议 8~14；渐变图不适用（区域内 p90 离中位 >35 自动跳过 = 安全阀） |
| 色数上限 | `--maxcolors N` | ≥1 | 不限 | ΔE 近邻归并压采购；另设**近重复兜底**（自动生效）：ΔE≤3 的低用量色对（肉眼不可分，玩家按色号采购必混）无条件并成一种——杜绝三种白同图；FS 模式自动跳过 |
| 敏感色优先 | `--sensitive 1` | 开 / 关 | **关** | 肤色保护：肤色像素在同色相族候选集内选色（候选集限制法，非 ΔE 加权） |
| 平色优先 | `--flat 0\|1\|2` | 关 / 标准 / 强力 | **fs 模式默认 1，nearest 默认 0** | 平坦区直通+零扩散（REPORT 方案 1 护栏，裸 FS 误差爆炸——CLI 实测 79%→18% 翻转率）+ 事后多数派归并 |
| 自适应候选集 | `--adaptive N` | ≥4 | **关** | 图像主色 → 品牌色盘受限候选集（≤N 色），治 Voronoi 分界翻转。⚠️ **代价（REPORT 明示）：色号被图像约束，可能不含你手里真有的色号**；⚠️ 渐变图收益有限（实测大浪 13.57%→13.25%，主色连续分布时受限集仍有近邻贴分界）——收益集中在主色结构简单的平色图 |
| 裁剪 | `--crop x,y,w,h` | 源图像素 | 不裁 | 裁到主体；EXIF 转正后的坐标 |
| 白边裁切 | `--autocrop` | 开关 | 不裁 | 自动检测并裁掉四缘「近白且匀色」边（扫描/翻拍件的画布外白边）。**断线排查第一刀**：白边不是画面，会把边缘线条稀释成断线、在四角生成假孤点（蒙德里安实测：右缘 21px 白墙 → 横黑线最右端断 2 格 + G20/G8 假孤点各 2 颗；裁掉后全宽连续）。判据 = 行/列亮度均值>205 且标准差<30（只看亮度会误吃画面白场），单边最多裁 15% |
| 分块 | `--split N` | ≥16 | 不分块 | 分块索引（含每块主色 top3）+ 分块施工图纸 + 按需块矩阵/ASCII |
| 按需块 | `--block K` | 配合 --split | 全部 | 只出第 K 块（>256 块时默认只出索引，必须按需） |
| ASCII 矩阵 | `--ascii auto\|0\|1` | — | auto | auto = 短边 ≤512 自动出 `blueprint-ascii.txt`；1 强出（>200 万格拒绝） |
| AI 辅导 | `--teach` | 开 / 关 | 关 | 落盘 `coaching.md` 辅导计划；`--level auto\|beginner\|intermediate\|advanced` / `--session-minutes N` |
| 参数对照 | `--compare-matrix` | 开 / 关 | 关 | 一条命令跑多方案 → `compare-matrix.png` 拼图 + `matrix.md` 指标表/复跑命令；`--matrix-variants nearest,fs,outline,merge` 自定方案 |
| 限定色盘 | `--inventory <json>` / 加 `--limit-palette` | 库存色盘 | 全色盘 | 工作流 B：默认只做覆盖/缺色分析；加 `--limit-palette` 才限定生成 |
| 自动迭代选参 | `--refine N` | 0（关）/ 组数上限 | **开（默认上限 6；参数阶梯共 5 组，全跑）** | 参数阶梯自动试 5 组（given / 区域锁定 / 低墨阈 / 锁定+墨阈 / avg）→ 每组算机器保真度（`evalGridQuality`：逐格ΔE + 30×断线率 + 0.5×翻转率）→ 选最低分继续管线 → `refine.md` 落盘全部轮次。**只对 nearest 生效**（fs 抖动跳过）；>200 万格跳过；不枚举网格数（网格由 agent 看 `--analyze` 推理）。复跑命令在 refine.md 头部 |
| 手工改格 | `--patch-cells 列:行=色号,…` / `--patch <json>` | 1-based 坐标 + 色盘色号 | 无 | 终审判定「真缺陷」后的**落地执行手段**：直接改格并重出全部交付图（sheet/compare/review/json/ascii 全部按改格后状态重出，review.md 重新生成待复检）。行内写法适合 VLM 判完即改；json 形态（`{patches:[{col,row,code}]}`）适合批量/留档。改格会记入 blueprint.md 处理报告 |
| 交付门禁 | `--review-gate 1\|0` / `--verify-review <outDir>` | 开 / 关 | **开** | review.md 判定/处置列全空 ⇒ 不算完成（`REVIEW_UNFILLED` + exit 3）；agent 看图填表后跑 `--verify-review` 签署（全填 ⇒ `REVIEW_SIGNED` + exit 0）。把「禁止空表交付」从文档口号变成程序闸门 |
| 透明阈值 | — | 固定 128 | 128 | 空位判定（`CELL_ALPHA_MIN`，暂未暴露参数） |

## 双工作流

```text
工作流 A（图纸生成 + 辅导）：图片 + 参数(--teach) → 色号表 / 施工图纸 / ASCII 矩阵 / 统计 / 采购清单
                              / 分块索引 / coaching.md 辅导计划 → AI 陪拼 → 复盘 → 库存回收 ↺
工作流 B（库存提取）：拼豆成品照 / 像素画作品图 / 拼豆图纸 / 色卡截图（紧贴或有间隙）
                      → 门禁放行 → 网格检测（差分 / 投影）→ 逐格取色 → ΔE 匹配色号
                      → 存为库存色盘 → 限定色生成 → 只补缺采购 ↺ 闭环
```

### 工作流 A：图纸生成（输出清单）

```bash
node scripts/run.js <图> [--grid 96] [--crop x,y,w,h] [--dither nearest|fs] [--outline 1]
               [--clean 0|1|2] [--sensitive 1] [--flat 1] [--maxcolors N]
               [--split N] [--block K] [--ascii auto|1] [--teach] [--out 输出目录]
```

| 交付物 | 实际落盘 |
|---|---|
| ① 色号表 | `blueprint.md`：色号 / 产品号 / 名称 / HEX / 颗数 / 占比 / 采购包数 |
| ② 网格坐标 | `blueprint.json`（逐格色号矩阵，-1=空位）+ `blueprint.png`（放大直映）+ **`blueprint-ascii.txt`**（文本矩阵，逐行核数/grep） |
| ③ 用色统计 | `blueprint.md` 用色统计段 + CLI 孤点诊断（孤点率判据，不评判色数多少） |
| ④ 采购清单 | `blueprint.md` 采购清单段（默认 200 颗/包） |
| ⑤ 辅导计划 | `coaching.md`（`--teach`）：难度评定 / 工时场次 / 里程碑 / 专属易错点 / 辅导问题 / 反馈思路 / 打卡 |
| 施工图纸 | `sheet.png`（网格线+行列编号+逐格色号+图例）；超大档 `--split N` 出 `sheet-block-*.png` |
| **视觉终审图** | `review.png`（≤200 万格自动出）：compare 基础上把机器可疑格（断线/劈叉/偏色，统一 0~100 伤害度标尺排序）红框标注 ≤12 处，左右两栏同位置——**agent 必须先看这张图再交付**。配套 `review.md` 逐框判定表（判定/处置两列由 agent 填写，填完 = 可审计终审证据）。**耗时量化：全链路增量 ≈0.2s**（定位 ~60ms + 渲染 ~150ms，实测 Mondrian 5.6MP g48~g128 稳定） |
| 分块索引 | `blocks-index.json`（每块豆数+主色 top3）+ `sheet-blocks.md`；`--block K` 时附 `block-K.json` + `block-K-ascii.txt` |
| 效果对比 | `compare.png`（原图 vs 拼豆效果并排——「像不像」一眼可判） |

### 超大网格档出图策略（>512，最高 8192）

| 交付物 | >512 档形态 |
|---|---|
| 色号表 / 统计 / 采购清单 | 正常输出（色数与格数无关） |
| 网格坐标 | ① 直映 PNG 总览（每格 1px）② **分块索引** `--split 52`（`blocks-index.json` 含每块豆数/主色 top3，>256 块默认只出索引）③ **逐块按需展开** `--block K` → `block-K.json` + `block-K-ascii.txt` |
| 辅导计划 | `--teach` 配合 `--split`：场次自动按块划分 |

- 源图上限 **100MP**；整张施工图纸画布 >64MP 自动跳过并提示 `--split`（防 OOM）
- 处理报告如实回报实际耗时

### 工作流 B：库存提取（全自动识别，9 环节）

| 环节 | 方案 |
|---|---|
| ① 输入 | 成品照 / 像素画作品图 / 拼豆图纸 / 色卡截图 |
| ② 裁剪（可选） | 输入含边框/背景时先 `--crop` |
| ③ 特征门禁 | 四分支 OR（方格色盘 / 稀疏点状 / 像素画成品 / 低色数插画）；照片直接拒 |
| ④ 网格检测 | 紧贴色块图走差分变色率；**有间隙色卡走投影检测**（背景占比 + 行列等距校验，检出后 `grid.mode='projection'`） |
| ⑤ 逐格取色 | 网格中心取样 → RGB 分桶归并抗噪 → 按格去重出色盘 |
| ⑥ 色号匹配 | Lab ΔE 最近色号 + 置信度分级；**低置信必须向用户确认，不静默采信** |
| ⑦ 库存持久化 | 色号集合 + 图例 + 匹配明细（可记录余量） |
| ⑧ 限定色生成 | `--limit-palette` 只在库存子集内映射 |
| ⑨ 缺色处理 | 就近替换建议（ΔE + 影响格数）+ 只补缺采购清单 |

**CLI 入口**：

```bash
#-- ① 扫成品/色卡 → 库存 JSON（低置信拒绝入库，确认后加 --accept-low-confidence）
node scripts/run.js <成品图或色卡> --scan inventory.json [--cols N --rows N] [--accept-low-confidence]

#-- ② 用库存生成：默认只做覆盖/缺色分析；加 --limit-palette 则只用库存色量化
node scripts/run.js <照片> --inventory inventory.json --grid 96 [--limit-palette] [--teach]
```

### 工作流 B 局限性（必须如实告知用户）

1. **只认网格化色块图，不认照片**——门禁结构性拒绝（设计使然）。门禁对高平坦度图会**误放**（实测单色 logo `unique=3` 也能过），由下游网格检测兜底拒绝。
2. **相邻同色格无可见边界时自动检测失败**——数清行列后加 `--cols N --rows N` 走等距取样。
3. **尺寸**——`detectGridByDiff` 对 >4096px 的图直接返回失败；大图先裁剪。≤256×256 最稳。
4. **拍摄质量影响取色精度**——低置信（ΔE>12）CLI 拒绝写库存，需人工确认后加 `--accept-low-confidence`。
5. **容差已标定但非万能**——极端噪声样张可能误拒/误放，误放后下游网格检测兜底。

### 格式兼容（2026-10-22）

- **progressive JPEG 自动转码**：解码遇 SOF2 不再直接拒绝，按 PowerShell System.Drawing → sips → magick → convert → Pillow 顺序找系统转换器转 PNG（60s 超时），EXIF 方向从原 JPEG 元数据补回后照常转正；找不到任何转换器时报可读错误并给出手工转格式建议。
- **16-bit PNG / 隔行 PNG 仍不支持**：抛可读错误。

## 处理报告（可解释输出——AI 微调的数据燃料）

| 决策数据 | 用户看到的话 |
|---|---|
| 参数快照 | 管线回显：nearest + clean1 + sensitive + flat1 |
| 归并色数 + ΔE | 「为你归并了 3 个低用量色（ΔE≤8），省 2 包采购」 |
| 清理格数 | 「清理了 47 格孤点杂色（强力档）」 |
| 孤点诊断 | 「孤点率 0.36%，色数 42 是图像本身色彩结构，不需要降档」 |
| 平色/敏感 | 「FS 平坦源区 4096 格（这些格不扩散误差）」 |
| 门禁/网格判据 | 「投影检出 16×12（有间隙色卡；背景占比 0.31）」 |

**微调闭环示例**：用户说「脸上杂色太多」→ 读处理报告 → 回「切强力档重跑」，而不是让用户翻参数表。

## 大模型推理框架（参数决策禁查表，2026-10-21 定稿）

**agent 五步**：① 先视觉看图（构图/主体/必保细节）→ ② 跑 `--analyze` 拿特征 JSON（stdout 纯 JSON，进度走 stderr；含主体代理 `subject.ratio`/`edgeCentroid`）→ ③ 视觉 × 特征推理决策并**写理由** → ④ **带 `--refine` 出图（默认开）**：机器先自动迭代 5 组参数选最优（逐格ΔE/断线率/翻转率，报告在 refine.md），agent 读报告核对选版理由 → ⑤ **视觉终审（硬门槛）**：CLI 会落盘 `review.png`（机器可疑格红框 ≤12 处），agent 必须【看图】逐框判断「真缺陷 or 机器误报」——有真缺陷按协议调参重跑（≤3 轮），全过才允许交付。**只看指标不看图 = 本末倒置，禁止交付**。完整方法论与五轮排查实录见 `references/visual-review-protocol.md`。**多方案比较用 `--compare-matrix`**（AI 看图选版，不按分数自动选）。

### 目检三轮闭环（2026-10-25 定稿，多模态大模型在环的落地形态）

> 用户裁定：模型应该反复对比图纸和原图，尽可能做到「像画出来的」——在有限格子内。机器指标（--refine）只保底，**形对不对/主体像不像只有视觉能判**。

1. **第 1 轮**：看 **review.png 红框**（机器已把可疑格框出来，注意力从 4096 格收敛到 ≤12 处）+ compare.png（左原图/右拼豆）→ 用一句话列**最伤形的 1~2 个缺陷**（例：「黑线在蓝块边断成虚线」「红块被劈成两色」）→ 按 SKILL.md 参数表选针对性旋钮重跑（断线→`--ink-min 0.10`/升网格；劈叉→`--region-lock 8`；偏色→换色盘/`--adaptive`）。
2. **第 2 轮**：只对比上一轮列的缺陷是否消失 + 有没有**引入新缺陷**（升网格会碎、加锁会平）→ 未消或新伤 → 再调。
3. **第 3 轮（上限）**：仍不达标就**如实交付**：明确告诉用户「已试 N 组参数，剩余缺陷是 X，原因是 Y（媒介表达力/源图质量），可选 Z（简化重绘/再升网格的代价）」。**禁止**静默交付明显残缺的图，也禁止无限重跑。

**判定落地**（判完能改，不是只能填表）：VLM 判出个别「真缺陷」格且调参无法根治时，用 `--patch-cells 列:行=色号,…` 直接改格——CLI 重出全部交付图并重新生成 review.md，回到第 2 轮复检确认闭环；空表交付由 `--review-gate` 程序闸门拦截（未填 ⇒ exit 3），填完跑 `--verify-review` 签署。

复杂画面在跑之前就有预警：CLI 会在开头打印「⚠ 复杂画面如实声明」（边缘密度/色彩熵/平色占比三判据），命中就必须先与用户对齐预期再出图。

特征语义：`colorEntropy` 色彩丰富度 · `edgeDensity` 细节密度 · `subject.centerEdgeDensity/edgeEdgeDensity/ratio` **主体代理**（中心 50% 框 vs 外圈边缘密度；ratio ≥1.35 主体居中，≤0.75 细节散在外圈 → 先裁主体）· `subject.edgeCentroid` 细节重心（偏移 >0.12 时提示裁切方向）· `flatRatio` 平色区占比 · `lumaSpread` 明暗对比 · `dominantColors` 主色结构 · `hints` 弱提示（仅参考）。

## 输入适配性（如实声明，2026-10-21 定稿）

> 用户实测：神奈川冲浪里翻拍版 96 格仍主体不凸显——**这是输入适配性问题，不是档位问题**。

1. 翻拍版先天缺陷：低分辨率 + 纸面纹理被忠实量化（管线是忠实转换器，垃圾进垃圾出）
2. 名画细节密度超出拼豆媒介表达力（浪花碎点需 256+ 格 = 6 万颗豆）
3. 无主体增强管线——主体靠输入图本身的构图对比保证

| 输入特征 | 应对 |
|---|---|
| 主体清晰、背景干净 | 直接出图（甜区） |
| 低分辨率翻拍版名画 | **先如实声明**预期落差，用户确认再跑 |
| 细节密集型绘画 | 同上 + 建议简化重绘版 |
| 剪影/Logo/扁平插画 | 最佳输入 |

# 附录 · AI 视觉终审协议与全过程实录（v1.2.0）

> 适用：pixel-bead-blueprint v1.2.0（2026-10-29）
> 一句话：**指标是线索，看图才是裁决。** 本 skill 跑在多模态大模型上——模型自带视觉能力，渲染出的每一张交付图都必须【亲眼看过、放大核过、对照过源图】才能交付。这是端侧离线工具做不到、而 AI skill 必须做满的事。

---

## 0. 为什么必须这么做（定位问题）

- **端侧离线工具**（传统拼豆 APP）没有视觉能力，只能算指标：逐格 ΔE、断线率、翻转率、孤点率。指标全绿但图很烂的失败模式真实存在（v1.1.1 前的「白底黑字被抹平但 ΔE 只有 3.83」就是实例）。
- **AI skill 跑在多模态大模型上**，模型本身就能看图：整图看构图、裁局部看线条、源图与成品并排对照、逐格核对色号。不用这个能力 = 因噎废食。
- 因此本协议把「看图」从文档口号升级为**程序闸门**：`review.md` 判定/处置两列全空 ⇒ `REVIEW_UNFILLED`（exit 3，不许交付）；agent 看图填表后 `--verify-review` 签署 ⇒ `REVIEW_SIGNED`（exit 0）。填完的判定表 = 「看过图」的可审计证据。

---

## 1. 全过程实录（2026-10-28，蒙德里安/示例案例，五轮迭代）

以下按实际排查顺序记录，每一轮都有「现象 → 假设 → 证据方法 → 修复 → 再看图验证」。

### 第 0 轮 · 用户反馈的三件事（也是本轮一切工作的起点）

1. 示例案例的「原图」本身就是拼完的成品——拿它走「照片→图纸」工作流 A 是循环演示；
2. 蒙德里安仍看得到断线；
3. 疑似「图纸与成品不符」。

### 第 1 轮 · 先证伪「图纸与成品不符」

- **方法**：写逐格核对脚本，比对 4 份产物 `blueprint.json ↔ blueprint.png ↔ sheet.png ↔ compare.png` 的每一个格子。
- **证据**：4096 格 0 不符。中途两次「误报」其实是核对脚本自身的 bug（图例 hex 无 `#` 前缀导致切片错位；compare.png 采样几何没对齐，用网格搜索对齐后归零）。
- **结论**：管线状态没有分歧；观感差异全部来自**图像质量缺陷**。问题聚焦到断线。

### 第 2 轮 · 断线根因第一环：翻拍白边

- **现象**：横黑线最右端被稀释成浅色/红色，四角出现假孤点（G20/G8）。
- **证据方法**：裁出源图四缘观察——源照片 2374×2350，画面实际只有 2324×2314，四缘是近白匀色的拍攝边。
- **修复**：`--autocrop`（逐行/列判据：亮度均值>205 且标准差<30 才裁，标准差护栏防止吃掉被黑线横穿的白色画块；单边上限 15%）。加 T45 回归锁。
- **看图验证**：横线右端连续了，假孤点消失。**但放大看，主竖线仍有间歇变宽。**

### 第 3 轮 · 断线根因第二环：抗锯齿毛边溢入邻格（本轮最核心的修复）

- **证据方法**：写全图扫描脚本——对每格统计源图「真墨水占比」（lum<50，注意红块 lum≈76 会污染 lum<100 的口径）与输出色号的矛盾（墨多却输出浅色 / 墨少却输出深色）。命中 104 格，集中在主竖线左侧一列、横带上下邻行。
- **根因**：`cellDominantColor` 的墨线保真判据只看「格内暗像素占比 ≥ `--ink-min`」。黑线的抗锯齿灰边溢进邻格（覆盖仅 10~15%、全部贴边分布），旧单一覆盖判据把这些邻格整格涂深 ⇒ 线宽在 1/2 格间抖动；卡通图轮廓外圈碎点同根。
- **第一版修复（中央墨水判据）**：墨线必须穿过格子中央 1/2×1/2 区域（中央覆盖 ≥6%）才认定整格是线。抖动格 104→0。**但 T35/T39 回归爆掉**：细线正压格界时（两侧各约 20%、中央覆盖为 0）整条线消失——中央判据只治毛边、误杀骑线。
- **第二版修复（骑线兜底，最终版）**：区分依据不在本格墨量（毛边 10~15% 与骑线 20% 分不开），而在**隔边邻格的墨量**：
  - 找出本格「主墨边条带」（四条 1/4 边条带中墨最多的一条）；
  - 测外侧邻格墨量 `nf`：
    - `nf ≥ 0.95`：墨带在邻格已有「整格的家」，本格只是溢出/毛边 ⇒ **留浅**（否则线宽 +1 格且逐行抖动）；
    - `nf` 部分覆盖（如对称骑线的 80%）：两格共担一条线 ⇒ **入线**（否则线整条消失）。
  - 中间还试过「本格墨量 ≥30% 即入线」的简单阈值——被 T35 证伪（骑线只有 20%），教训：**两个反例的分布重叠时，必须换维度找判据，不能硬调阈值**。
- **回归锁**：新增 T46 双向测试——场景 A（整格黑带 + 4px 溢入邻格 ⇒ 邻格必须整列留浅）；场景 B（8px 细线正压格界 ⇒ 两侧格必须入线）。58 项全过。
- **看图验证**：裁源图与成品同区域并排放大，横竖线恒定 2 格宽、全程连续；对比 v1.1.2 旧版渲染（毛边杂乱）与新版（线缘齐直）差异肉眼可见。

### 第 4 轮 · 「三种白同图」（看图才看得出来的问题）

- **现象**：v1.1.3 重跑后图例出现 H10(`#ECEAEB`)/H17(`#F0EEEF`)/H1(`#FBFBFB`) 三种白，ΔE≈1~6，肉眼不可分。拼豆玩家按色号采购施工必混。
- **根因**：`--maxcolors` 归并只在「色数超上限」时触发；7 色输出 ≤ 上限 8，归并整段跳过——**色数达标 ≠ 没有近重复**。
- **修复**：归并段尾部加近重复兜底（ΔE≤3 的低用量色对无条件并入大色），并把该兜底改为**不依赖 `--maxcolors` 恒生效**（FS 抖动模式除外）。
- **看图验证**：样张收敛为 5 色 4096 颗（红白黑蓝黄经典五色），平坦翻转率 0%。

### 第 5 轮 · 视觉终审与补刀（协议正式执行的示范）

- **机器红框**：review.png 标了 12 处「断线」——放大逐框看，全部是骑线毛边误报（线本身恒定 2 格宽）。逐框填表（判定=误报 + 一句话理由）→ `--verify-review` ⇒ REVIEW_SIGNED。
- **补刀 1**：右下角黄块右缘的白条——裁源图对照确认是真实画布边（黄块没画到边），但成品只捕到 2 格，其余被量化成黄色。用 `--patch-cells` 把右缘 6 格归位成白，与源图一致。
- **补刀 2**：col 57 一格孤点溢出、col 64 底部假白格，同法归位。**改格后全部交付图自动重出，再整图看一遍确认**。
- **示例案例**：多轮参数对比（22/26/21 色）逐版看图，终版 21 色 9888 颗——轮廓全程连续、无碎点光环；脚间蓝色冰影经源图核对是**真实细节**，如实保留（源图真实特征 ≠ 缺陷）。
- **Progressive 案例**：同一画作渐进式编码版本，同参数出图；4 颗照片噪点斑（1~2 颗的 G8/M7/C12）定位坐标后归位，5 色 0 孤点。

### 附：画廊 v3（交付界面层）

用户在手机上反馈「滑到图片上页面就滚不动了」——旧版 `touch-action:none` 劫持了触摸。v3 改为 `pan-y pinch-zoom`：单指滑动=页面正常滚动；双击图片=放大↔复原；放大后单指拖动、双指捏合缩放；电脑端 Ctrl/⌘+滚轮缩放、普通滚轮放行页面滚动。

## 2. AI 视觉终审协议（SOP，每个案例必须走满）

### 2.1 五步闭环（上限 3 轮）

```
跑管线 → 【看图】→ 一句话定性最伤形的 1~2 个缺陷 → 针对性调参/patch 重跑 → 【再看图】
```

- 看什么（缺一不可）：`compare.png`（左源图/右成品，整图构图+逐区域对照）、`review.png`（机器红框逐框判定）、`sheet.png`（施工图纸可读性：网格线/行列编号/格内色号）。
- 怎么定性：一句话说清「哪里、什么问题、多伤形」（例：「主竖线左侧整列间歇变深，观感=断线」）。说不出来的缺陷不存在；说出来的缺陷必须对应一个可操作的旋钮。
- 3 轮仍不达标：如实声明残缺点后交付，禁止静默。

### 2.2 「看」的可操作技法（把多模态能力用满）

1. **整图先看构图**：贴不贴近原作，第一眼先看大结构（色块位置、线条走向）。
2. **裁局部放大看线条**：对可疑区域（源图与成品同一几何区域）分别裁剪放大并排看。蒙德里安 64 格下每格 36px 渲染，断线/抖动/锯齿一眼可辨；示例图轮廓在 g96 下单格 10px，碎点光环也藏不住。
3. **全图扫描找嫌疑格，再逐格看**：写一次性脚本统计「源图真墨占比 vs 输出深浅」矛盾格（全图 104 格比人眼扫 4096 格快且不漏）。注意墨量口径：判黑线用 lum<50，lum<100 会被红色污染。
4. **机器红框 ≠ 真缺陷**：逐框放大判定，误报也要写明理由（「骑线边格：源线宽约 1.9 格，输出稳定 2 格宽，被框格为抗锯齿毛边」）。填完的表才是终审证据。
5. **源图真实细节 ≠ 缺陷**：画布裂纹、签名、右缘白边条、示例图脚间冰影——先裁源图核对，是真细节就如实保留，是噪点斑（1~2 颗孤立杂色）就用 `--patch-cells` 归位。
6. **改格后必看**：`--patch-cells` 会全量重出交付图，重出后整图再看一遍，防止改 A 坏 B。

### 2.3 程序闸门

- `--review-gate 1`（默认开）：判定表没填 ⇒ `REVIEW_UNFILLED` exit 3。
- `--verify-review <outDir>`：填完后签署 ⇒ `REVIEW_SIGNED` exit 0。注意它是**独立命令**（传 outDir），不是 run 的开关。
- 判定口径写死在 review.md 头部：画布裂纹/扫描噪点/有意纹理=误报；线断/劈叉/明显偏色=真缺陷。

## 3. 踩坑清单（每一条都真实踩过）

| 坑 | 教训 |
|---|---|
| 只报指标不看图就交（「断线率 0%」但图上抖动明显） | 指标只是线索；交付前必须看图，协议已程序化 |
| 直觉判「效果不错」不放大核对 | 被用户当场抓到碎点光环；看图必须放大到缺陷可见的倍率 |
| 拿拼完的成品当「原图」演示工作流 A | 循环论证；先确认每张输入图的身份与用途 |
| 把源图真实细节（白边条/冰影/裂纹）当缺陷修掉 | 先裁源图核对再动手；真细节如实保留 |
| 红色污染暗像素口径（lum<100 含红） | 判黑线用 lum<50 |
| `decodeJpeg` 读 PNG 报「missing SOI」 | 按扩展名/魔数选解码器 |
| `--verify-review` 当 run 开关混用 | 它是独立命令，接收 outDir |
| 阈值式判据调不平时硬调 | 反例分布重叠时换维度（本格墨量 → 邻格墨量）找判据，并让回归测试锁住两个方向 |
| 归并逻辑只在「超上限」时触发 | 色数达标 ≠ 无近重复；ΔE≤3 兜底恒开 |
| `node -e` 内联脚本写复杂逻辑 | 反复被引号/模板串坑；一律落脚本文件再跑 |
| zip 打包后不验内容（旧字节、旧符号） | 重打包后 `sync` + `unzip -p \| grep` 验证新符号确实在包里 |

## 4. 这套协议在比赛里的差异化价值

- 端侧 APP：只能算指标，坏图静默交付；
- 纯文生图模型：给一张「像像素画的图」，没有色号、没有图纸、无法施工、更无人核验；
- **本 skill**：管线出图纸 + 机器红框圈嫌疑 + **AI 亲眼看图逐框裁决** + 改格回路闭环 + 判定表可审计。看图这一步是模型原生多模态能力与管线工具链的结合点——管线把 4096 格收敛到 ≤12 个红框，AI 把 12 个红框逐个看掉，人只看结论与证据。
