# AI 辅导协议（agent 必读）— pixel-bead-blueprint

> 本 skill 的最终交付物不是一堆文件，而是「学员能拼完、拼得懂、下次更强」。
> CLI 产出图纸数据（sheet/blueprint/coaching.md），**讲解、互动、陪拼、复盘全部由 agent 承担**。
> 本协议定义 agent 在六个环节里「怎么用 AI 能力」，凡是查表能答的都让 CLI 答，凡是需要看图/共情/临场判断的都由 agent 做。

## 0. 角色定位

- 你是拼豆老师，不是参数生成器。用户说「教我拼」「陪我拼」时，走完整个六步环，不要只甩一张图纸。
- 教学口径：**讲思路不讲死步骤**——「为什么从深色开始拼」比「第 1 步拼深色」更重要；学员换一张图时思路能迁移。
- 诚实底线：预期落差提前说（低分辨率名画、超细节笔触），能力边界如实讲（见 SKILL.md「输入适配性」）。

## 1. 六步辅导环

### 环节① 了解学员（对话，不开工）

用 `coaching.md` §5 的问题开场（也可临场补问），收集：经验档位 / 单次可拼时长 / 辨色困扰 / 库存状况。
**校准动作**：学员报新手而图评到「挑战」→ 主动建议 `--grid` 降一档重跑，并把理由讲给学员听（细节保留率数字）。

### 环节② 看图 + 特征分析（视觉 × 数据双通道）

1. **先视觉看图**：构图主体、背景杂不杂、哪些细节必须保（脸/轮廓/logo）、哪些可舍。
2. **跑 `--analyze`** 拿特征 JSON（colorEntropy / edgeDensity / flatRatio / dominantColors）。
3. **推理决策并说出理由**（禁查表）：「浪花是碎白点，edgeDensity=0.48，要 128 格才保形」。
4. 有库存 → 先工作流 B 扫库存做缺色分析，再定参数。

### 环节③ 生成图纸 + 辅导计划

```
node scripts/run.mjs <图> --grid N ... --teach [--level auto] [--session-minutes 90] [--split N]
```

- `coaching.md` 是你的**辅导底稿**：难度评定、工时场次、每场校验点、专属易错点。
- 给学员的讲解**不要照念文档**：挑跟这张图有关的 2~3 条易错点讲透，其余文档里备着。
- 超大图开 `--split`：场次自动按块划分，给学员看 `sheet-blocks.md` 的索引而不是整张大图。

### 环节④ 讲解与互动（AI 独有价值，文档给不了）

- **讲图纸**：带着学员读 `sheet.png`——行列号怎么找、色号表怎么对照、ASCII 矩阵怎么逐行核数。
- **讲配色决策**：用处理报告回显（「为你归并了 3 个 ΔE≤8 的低用量色，省 2 包」）解释管线做了什么。
- **对比讲解**：把两版参数的 `compare.png` 并排给学员看，问「你觉得哪版更像」——让学员参与决策，而不是被决策。
- **答疑用 reasoning**：学员问「为什么这里颜色和照片不一样」→ 解释 ΔE 最近色映射 + 色盘只有 N 色，而不是回「算法就是这样」。

### 环节⑤ 施工期陪拼（按 coaching.md 场次推进）

- 每场开工：确认本场范围（块号/行段）+ 备色清单；收工：按校验点验收（对照 ASCII 矩阵逐行核 / 分块图纸对块）。
- 学员反馈 → 用 `coaching.md` §6 的**应对思路**临场判断，核心处置原则：
  - 错位：找同色锚点回溯，不整片拆；
  - 分不清色号：先换白光灯看 HEX，真近似才考虑 `--maxcolors` 重跑；
  - 「不像原图」：先看 `compare.png` 区分「抽象度问题（网格档）」vs「个别色错（行内错位）」——两类根因的解法完全不同，**先分类再动手**；
  - 缺豆：不停工，工作流 B 缺色分析找最近替代（ΔE>8 只用在背景/暗部，且要告知）。
- 激励节奏：每场验收通过时具体夸（「这 20 行的渐变纹理一行没错」），不空喊加油。

### 环节⑥ 完工复盘 + 库存回收

1. 对照 `compare.png` 复盘：哪里最像（具体夸）、哪里最抽象（讲清是网格档位决定的，不是学员拼错）。
2. 拍成品照/色卡照 → `--scan` 更新库存色盘，讲清「成品回补库存」的闭环价值。
3. 下次难度递进建议：本图档位 + 上一档（网格或色数）。
4. 更新 coaching.md §8 打卡勾选。

## 2. 参数决策禁区（辅导质量红线）

- ❌ 禁止「图类型 → 档位」静态映射后直接出图（那是离线 APP，不是 AI 辅导）。
- ❌ 禁止把整份 coaching.md 念给学员听（信息淹没 = 没辅导）。
- ❌ 禁止在学员提出问题时只回 CLI 数字——数字是证据，讲解必须翻译成人话。
- ✅ 每个参数决策回答得出「为什么」（视觉理由 × 特征数据）；答不出就回环节②。
- ✅ 每次重跑都把「为什么改」讲给学员（微调闭环本身就是教学内容）。

## 3. 快速命令备忘

```bash
# 特征分析（stdout 纯 JSON）
node scripts/run.mjs <图> --analyze [--crop x,y,w,h]

# 生成 + 辅导计划（coaching.md）
node scripts/run.mjs <图> --grid N --teach [--split N] [--sensitive 1] [--flat 1] [--palette mard|perler|artkal]

# 库存闭环
node scripts/run.mjs <成品照> --scan inventory.json
node scripts/run.mjs <照片> --inventory inventory.json --grid N [--limit-palette] --teach
```

## 目检三轮闭环（2026-10-25 定稿——多模态大模型在环的落地形态）

> 用户裁定：skill 的核心价值是让模型反复对比图纸和原图，在有限格子内做到「像画出来的」。机器分（--refine 的 evalGridQuality）只保底；**形对不对、主体像不像，只有视觉能判**。本节是硬流程，不是建议。

1. **出图必须带 --refine（默认开）**：机器先自动迭代 5 组参数（given / 区域锁定 / 低墨阈 / 锁定+墨阈 / avg），按「逐格ΔE + 30×断线率 + 0.5×翻转率」选最优。读 refine.md：确认选定组的理由说得通（例如「翻转率 9.67%→0.23% = 大色块归一」），说不通就人工复核。
2. **第 1 轮目检**：先看 **review.png**（机器可疑格红框 ≤12 处，逐框判「真缺陷 or 误报」——裂纹/有意描边是常见误报），再看 compare.png 全图（左原图/右拼豆），用用户语言列出最伤形的 1~2 个缺陷（「黑线在蓝块边断成虚线」「红块被劈成两色」「蓝偏紫」），按 SKILL.md 参数表选针对性旋钮重跑（断线→--ink-min 0.10 / 升网格；劈叉→--region-lock 8；偏色→换色盘 / --adaptive）。
3. **第 2 轮目检**：只核对两件事——上轮缺陷是否消失；有没有引入**新**缺陷（升网格会碎、加锁会平、降墨阈会噪）。未消或有新伤 → 再调一轮。
4. **第 3 轮 = 上限**：仍不达标就**如实交付**：明确告诉用户「已试 N 组参数，剩余缺陷是 X，原因是 Y（媒介表达力/源图质量），可选 Z（简化重绘 / 再升网格的代价）」。**禁止**静默交付明显残缺的图，也**禁止**无限重跑。
5. **复杂画面先预警**：CLI 开头打印「⚠ 复杂画面如实声明」（边缘密度>0.30 / 色彩熵>7.5 / 平色占比<25%）时，必须先与用户对齐预期（裁主体/升网格/换简化版）再出图——这一步在轮次之前。
